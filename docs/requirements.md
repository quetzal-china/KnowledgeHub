# 需求文档

## 1. 项目背景

### 问题描述
在学术研究和技术学习中，用户常常面临以下问题：
- 不知道搜索什么关键词
- 信息分散在多个平台（arXiv、知乎、博客等）
- 手动整理耗时耗力
- 难以评估内容质量

### 解决方案
构建一个 AI 驱动的知识检索系统，自动完成：
1. 关键词提取：将模糊描述转化为精准搜索词
2. 多源采集：从 arXiv、知乎等平台自动抓取内容
3. 智能处理：利用 LLM 进行内容总结和质量评估
4. 可视化输出：生成图表和结构化文档

## 2. 业务需求

### 目标用户
- 学术研究者：需要快速了解某个领域的研究现状
- 技术学习者：需要系统性地学习某个技术主题
- 项目开发者：需要收集相关技术方案和最佳实践

### 核心价值
- **效率提升**：自动化采集和整理，节省手动搜索时间
- **质量保证**：AI 评估内容质量，过滤低质量信息
- **知识沉淀**：输出结构化文档，便于长期积累和复用

## 3. 功能需求

### 3.1 关键词提取模块
- **输入**：用户的模糊描述（中文或英文）
- **处理**：LLM 提取 3-5 个精准搜索关键词
- **输出**：关键词列表及权重

### 3.2 多源搜索模块
- **数据源 1**：arXiv（学术论文）
  - 搜索方式：TinyFish Search API
  - 抓取方式：Scrapy + XPath 解析 HTML
  - 数据字段：标题、作者、摘要、分类、提交时间
- **数据源 2**：知乎（技术问答）
  - 搜索方式：TinyFish Search API
  - 抓取方式：Scrapy 调用 API 解析 JSON
  - 数据字段：问题标题、回答内容、点赞数、评论数

### 3.3 数据处理模块
- **数据清洗**：去除 HTML 标签、处理缺失值、格式转换
- **质量评估**：基于点赞数、作者权威性、时效性进行评分
- **内容总结**：LLM 提取每篇文章的核心观点（100-200 字）

### 3.4 可视化模块
- **趋势图**：论文/回答数量随时间变化
- **词云**：关键词频率分布
- **柱状图**：Top 作者/机构排名
- **散点图**：点赞数 vs 评论数关系

### 3.5 输出模块
- **Markdown 输出**：结构化文档，包含摘要、图表、引用
- **JSON 输出**：便于程序处理的原始数据
- **Streamlit 前端**：Web 界面展示结果

## 4. 非功能需求

### 4.1 性能需求
- 单次查询处理时间 < 30 秒
- 支持并发请求（多线程/异步）
- 内存占用 < 500MB

### 4.2 可靠性需求
- 网络请求失败自动重试（最多 3 次）
- API 限流时自动降级
- 错误日志记录和告警

### 4.3 可维护性需求
- 模块化设计，每个模块独立可测试
- 代码符合 PEP 8 规范
- 完整的注释和文档

### 4.4 可扩展性需求
- 易于添加新数据源（如 B站、微信公众号）
- 易于更换 LLM 模型
- 易于调整可视化样式

## 5. 技术需求

### 5.1 后端技术
- **并发处理**：支持多线程/异步请求，提高采集效率
- **错误处理**：自动重试机制，最多 3 次
- **日志记录**：记录运行状态和错误信息
- **配置管理**：使用 .env 文件管理 API Key

### 5.2 前端技术
- **Web 界面**：使用 Streamlit 构建
- **交互功能**：输入关键词、查看结果、导出数据
- **响应式设计**：支持不同屏幕尺寸

### 5.3 数据存储
- **原始数据**：CSV/JSON 格式存储在 data/ 目录
- **处理结果**：Markdown 格式存储在 output/ 目录
- **配置文件**：.env 文件存储敏感信息

### 5.4 部署方式
- **本地运行**：Python 虚拟环境
- **依赖管理**：requirements.txt
- **版本控制**：Git

## 6. 数据流设计

```
用户输入（模糊描述）
    ↓
LLM 提取关键词
    ↓
TinyFish 搜索相关 URL
    ↓
选择数据源
    ├── arXiv：Scrapy + XPath 解析 HTML
    └── 知乎：Scrapy 调用 API 解析 JSON
    ↓
数据清洗 & 质量评估
    ↓
LLM 内容总结
    ↓
Matplotlib 可视化
    ↓
生成 Markdown/JSON 文件
```
